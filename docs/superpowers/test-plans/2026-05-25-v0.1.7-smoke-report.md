### R7: Empowered Strikes Damage Bonus -- FAIL (BLOCKING)

**Selected:** Empowered Strikes in the cast dialog.
**Expected:** Each Manifestation Strike activity gains an additional 1d8 damage part of the chosen damage type.
**Actual:** No additional damage part added. Both Melee and Ranged activities retain only their base `2d8 + @mod bludgeoning`.

**Root cause:** `empoweredStrikes.patch` in modification-registry.js (line 115) iterates with:
```
for (const [actId, act] of Object.entries(activities))
```
`activities` is an `ActivityCollection`, which extends `Map`. `Object.entries()` on a Map returns an empty array because Map entries are not own enumerable string-keyed properties. The loop body never executes, so the patch returns an empty update object.

**Fix:** Replace `Object.entries(activities)` with `activities.forEach((act, actId) => { ... })` or `for (const [actId, act] of activities)` (Map iterator protocol).

### R8: Damage Type Set by Cast Dialog -- FAIL (BLOCKING)

**Selected:** "Radiant" damage type in cast dialog.
**Expected:** Manifestation Strike damage types change from bludgeoning to radiant.
**Actual:** Both activities still show `types: ["bludgeoning"]`.

**Root cause:** `setStrikeDamageType` in cast-flow.js (line 124) uses the same `Object.entries()` pattern on the ActivityCollection. The iteration produces zero entries, so no damage type update occurs.

**Fix:** Same as R7. Replace `Object.entries(strike.system?.activities ?? {})` with a Map-compatible iteration. The `?? {}` fallback is fine for the null case but is never reached because `activities` is always an ActivityCollection (Map).

**Note:** R7 and R8 share a single root cause. Fixing one pattern fixes both, but both call sites need the same change.

### Harrowing Presence End-to-End -- FAIL (NON-BLOCKING, INTEGRATION)

**Setup:** Tulpa with Harrowing Presence active. NPC placed 5ft away (within 10ft aura radius). Combat started, turns advanced to NPC's turn.

**Expected:** Aura Effects 1.5.2 propagates the aura's `changes` (inHarrowingAura flag + auraDC) onto the NPC as a marker effect. At the NPC's turn start, `combatTurnStart` hook reads the flag and prompts a Wisdom save.

**Actual:** The aura AE renders visually on the canvas (golden/yellow radius square around the Tulpa). The source data contains the correct changes. But Aura Effects does not create a marker effect on the NPC. The NPC has no effects, no `inHarrowingAura` flag. The `combatTurnStart` hook exits early at line 14 (`if (!actor.getFlag(MODULE_ID, "inHarrowingAura")) return`).

**Diagnosis:** This appears to be an Aura Effects 1.5.2 integration issue. Possible causes:

1. The NPC token was placed while the aura was already active -- Aura Effects may only check proximity on token movement events, not on initial placement.
2. Token movement was attempted (nudge by 1px) but still no propagation.
3. The `type: "auraeffects.aura"` data model may require different configuration (e.g., `collisionTypes`, `evaluatePreApply`, or `script` settings) than what manifest-tulpa provides.
4. The runtime `changes` getter returning empty (while `toObject().changes` has 2 entries) may indicate Aura Effects processes changes through a different path that manifest-tulpa's setup doesn't trigger.

**Recommended investigation:** Test the same aura AE configuration manually in Aura Effects' own UI to verify whether the issue is in manifest-tulpa's AE template or in Aura Effects' collision/propagation logic.

## Bugs Found

### Bug A: Object.entries() on ActivityCollection (BLOCKING)

**Severity:** Critical (breaks core functionality)
**Affects:** R7 (Empowered Strikes), R8 (damage type selection)
**Files:**
- `cast-flow.js` line 124: `for (const [actId, act] of Object.entries(strike.system?.activities ?? {}))`
- `modification-registry.js` line 115: `for (const [actId, act] of Object.entries(activities))`

**Root cause:** In dnd5e 5.2.5, `item.system.activities` is an `ActivityCollection` which extends `Map`. `Object.entries()` on a Map returns `[]` because Map entries are not own enumerable string-keyed properties. The fix is to use Map-compatible iteration: `activities.forEach((act, actId) => { ... })` or `for (const [actId, act] of activities)`.

**Impact:** The chosen damage type is never applied to the Manifestation Strike. Empowered Strikes' extra 1d8 is never added. The Tulpa always deals bludgeoning damage regardless of the dialog selection.

### Bug B: Harrowing Presence Aura Not Propagating (NON-BLOCKING)

**Severity:** Medium (feature non-functional, but no crash)
**Affects:** Harrowing Presence end-to-end
**File:** modification-registry.js line 148-181

**Symptom:** Aura Effects 1.5.2 renders the visual radius but does not create marker effects on in-range tokens. The `changes` array is correctly stored in the AE source data but the runtime `changes` getter returns empty.

**Possible cause:** Aura Effects 1.5.2 may process `auraeffects.aura` type AE changes through a non-standard path. The module's data model shows a `stashedChanges` field (currently empty) which may be involved. Further investigation needed with Aura Effects documentation or source.

### Bug C: Skill Affinity Label Abbreviations (COSMETIC)

**Severity:** Low (cosmetic only, no functional impact)
**Affects:** R19
**File:** modification-registry.js line 241

**Symptom:** Skill Affinity modifications display 3-letter abbreviation codes (STE, PRC, ATH, etc.) instead of full skill names.

**Fix:** Replace `${skill.toUpperCase()}` with a lookup from a skill name table, e.g.:
```js
const SKILL_NAMES = { acr: "Acrobatics", ani: "Animal Handling", arc: "Arcana", ... };
name: `Skill Affinity: ${SKILL_NAMES[skill] ?? skill.toUpperCase()}`
```

### Bug D: Dismiss Race Condition with times-up (COSMETIC)

**Severity:** Low (cosmetic console error, no functional impact)
**Affects:** Dismissal trigger 1 (duration expiry)

**Symptom:** When times-up expires the anchor AE, both times-up and manifest-tulpa try to delete the Tulpa token. The second deletion throws `EmbeddedCollection.get: undefined id does not exist`. Net result is correct.

**Fix (optional):** Add a try/catch around the token deletion in dismiss-flow.js line 43 (already present) and suppress the error more gracefully in the times-up interaction path. Alternatively, detect that times-up is the deletion source and skip the redundant token delete.

### Bug E: Dismiss Animation Timeout (COSMETIC)

**Severity:** Low (5-second delay before token removal)
**Affects:** Dismissal trigger 2 (anchor AE manual deletion)

**Symptom:** `playDismiss` times out after 5000ms with "dismiss animation timed out". This delays the token deletion by 5 seconds. Likely caused by missing jb2a animation assets for the radiant damage type dismiss preset, or sequencer not being ready.

At 5th level (casting with a 5th-level slot), the available modification slots are **2**. This was lower than expected. The slot budget formula should be documented or verified against the spell spec. Two slots significantly limits the number of modifications that can be combined in a single cast.

## Recommendations for v0.1.8

1. **Fix Bug A immediately.** This is the only blocking issue. Two lines need to change from `Object.entries()` to Map-compatible iteration. This unlocks the damage type system and Empowered Strikes, which are core to the spell's identity.

2. **Investigate Bug B** by testing the Harrowing Presence aura AE configuration directly in Aura Effects 1.5.2's own creation UI. If a manually created aura with the same `changes` array propagates correctly, the issue is in how manifest-tulpa creates the AE. If it also fails, the issue is in Aura Effects 1.5.2 itself or in the module's compatibility with Foundry V13.351.

3. **Fix Bug C** with a skill name lookup table. Quick win for polish.

4. **Bugs D and E** are low priority and can be addressed in a polish pass.

5. **Increase test coverage** for Size Shift (R14), Multiattack (R15), Telepathic Link (R16), and Relentless (R17) in the next test cycle.
